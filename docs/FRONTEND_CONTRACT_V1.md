# Frontend Contract V1

Last updated: 2026-06-05

## Purpose

This document defines the current frontend-facing contract for Portfolio Analyst Agent V2.

It is meant to let frontend work proceed now, using the tracked April 2026 sample bundle, without waiting for new monthly data runs.

## Recommended UI Source

For frontend development, use the generated bundle:

- `frontend/Example_frontendV1/src/data/monthlyReviewBundle.json`

That bundle is the most stable design surface right now because:

- the repo does not track the raw `artifacts/monthly_review/<snapshot_date>/<fund>/...` run folders
- the bundle is already shaped for client consumption
- the current sample UI reads directly from the bundle

The bundle is generated by:

- `scripts/build_monthly_review_frontend_bundle.py`

From:

- `artifacts/monthly_review/<snapshot_date>/batch_index.json`
- each fund's `run_payload.json`
- each fund's `run_summary.md`

## Bundle Shape

Top-level fields:

- `bundle_generated_at: string`
- `snapshot_date: string`
- `as_of_date: string`
- `fund_count: number`
- `funds: FundBundle[]`

Each `FundBundle` contains:

- `slug: string`
- `fund: string`
- `snapshot_date: string`
- `review_run_id: string`
- `run_summary_markdown: string`
- `run_payload: RunPayload`
- `index_entry: BatchIndexEntry`

## RunPayload Shape

`run_payload` contains:

- `review_run_metadata`
- `fund_snapshot_summary`
- `change_brief`
- `sizing_considerations`
- `challenge_brief`

### review_run_metadata

Expected fields:

- `fund: string`
- `snapshot_date: string`
- `prior_snapshot_date: string`
- `as_of_date: string`
- `review_run_id: string`
- `parser_version: string`
- `mapping_version: string`
- `governance_version: string`
- `algo_version: string`
- `run_mode: string`
- `generated_at: string`
- `source_file_hashes: Record<string, string>`

### fund_snapshot_summary

Contains:

- `coverage`
- `memory_summary`
- `trigger_summary`

`coverage` includes:

- `target_match_pct: number`
- `benchmark_match_pct: number`
- `benchmark_expected_status: string`
- `raw: object`

`memory_summary` includes counts such as:

- `thesis_ledger_count`
- `open_challenges_count`
- `exceptions_count`
- `watch_items_count`
- `approved_count`
- `applied_count`
- `proposed_count`

`trigger_summary` includes counts such as:

- `candidate_count`
- `fired_count`
- `borderline_count`
- `suppressed_count`
- `not_triggered_count`
- `not_evaluable_count`

## Change Brief Contract

`change_brief` is required in both the deterministic harness and live agent flow.

Header:

- `fund`
- `snapshot_date`
- `prior_snapshot_date`
- `as_of_date`
- `review_run_id`
- `parser_version`
- `mapping_version`
- `governance_version`
- `algo_version`
- `run_mode`

Primary content:

- `executive_summary: string`
- `material_movers: MaterialMover[]`
- `sizing_artifact_summary: object`
- `memory_updates_summary: object`
- `triggers_fired_summary: object`
- `evidence_index: EvidenceRow[]`

Each `MaterialMover` is expected to support:

- `acid: string`
- `acid_type: string`
- `active_rolled_exposure: number | null`
- `target_rolled_exposure: number | null`
- `benchmark_rolled_exposure: number | null`
- `vir_stf: number | null`
- `vir_delta_stf: number | null`
- `vir_rank_change_by_stf: number | null`
- `narrative: string`
- `pm_takeaway?: string`
- `review_question?: string`
- `what_would_change_view?: string`
- `decomposition_drivers?: object`
- `evidence_pointers: EvidencePointer[]`

Current runtime expectation:

- live agent schema caps `material_movers` at 3
- deterministic sample data may contain more than 3

Frontend guidance:

- build for variable list length
- do not assume `pm_takeaway`, `review_question`, or `what_would_change_view` are present in the April sample

## Sizing Considerations Contract

`sizing_considerations` is expected to contain:

- `header: object`
- `perspective_summary: object`
- `algo_vs_positioning_agreement: SizingRow[]`
- `algo_vs_positioning_disagreement: SizingRow[]`
- `largest_algo_mom_changes: SizingRow[]`
- `coverage_notes?: array`
- `evidence_index: EvidenceRow[]`

Each `SizingRow` should be treated as semi-structured but generally includes:

- `acid: string`
- `perspective?: string`
- `narrative: string`
- `evidence_pointers: EvidencePointer[]`

It may also include numeric fields such as:

- `active_rolled_exposure`
- `target_rolled_exposure`
- `benchmark_rolled_exposure`
- `algo_active_weight`
- `algo_abs_weight`
- `vir_stf`
- `vir_delta_stf`

Frontend guidance:

- the narrative lists are safe primary UI surfaces
- numeric subfields should be treated as optional

## Challenge Brief Contract

`challenge_brief` is optional and may be `null`.

When present, it contains:

- `header: object`
- `items: ChallengeItem[]`
- `evidence_index: EvidenceRow[]`

Each `ChallengeItem` is expected to support:

- `challenge_id: string`
- `trigger_candidate_id: string`
- `acid: string`
- `trigger_type: string`
- `position_summary: object`
- `disagreement_statement: string`
- `challenge: string`
- `next_review_checkpoint: string`
- `evidence_pointers: EvidencePointer[]`

Frontend guidance:

- always handle `challenge_brief === null`
- always handle `items.length === 0` defensively even though the validator rejects empty challenge briefs

## Evidence Contract

`evidence_pointers` appear inside movers, sizing rows, and challenge items.

Each pointer currently looks like:

- `artifact_path: string`
- `row_id: string`

`evidence_index` is a list used for audit/context display.

Treat `evidence_index` as displayable metadata rather than a strict relational schema. The exact fields may evolve.

## BatchIndexEntry Contract

`index_entry` currently contains:

- `fund: string`
- `snapshot_date: string`
- `review_run_id: string`
- `output_dir: string`
- `change_brief_json: string`
- `sizing_considerations_json: string`
- `challenge_brief_json: string`
- `run_summary_md: string`
- `trigger_summary: object`

Frontend guidance:

- use these paths as references only
- do not assume those files are checked into Git

## PM Review Contract

There is a second presentation surface for live agent runs:

- `pm_review.md`
- `pm_review.html`

These are generated from the Change Brief by:

- `scripts/render_pm_review.py`
- `src/portfolio_analyst_agent/pm_review_renderer.py`

Important current state:

- the April frontend sample bundle does not include `pm_review.md` or `pm_review.html`
- the live write-tool flow does generate them

Frontend recommendation:

- do not make `pm_review` a required dependency for the main review UI yet
- treat it as an optional secondary presentation surface

## Current Naming Mismatch

There is a real naming mismatch between the deterministic sample flow and the live agent write flow.

Deterministic sample references:

- `change_brief_draft.json`
- `sizing_considerations_draft.json`
- `challenge_brief_draft.json`

Live write tools persist:

- `change_brief.json`
- `sizing_considerations.json`
- `challenge_brief.json`
- `pm_review.md`
- `pm_review.html`

Frontend recommendation:

- design against the in-memory bundle shape, not raw filenames
- treat artifact filenames as unstable until the backend unifies them

## Stable UI Baseline For Shivika

Safe surfaces to design around now:

- fund selector
- bundle-level snapshot and as-of metadata
- coverage, memory, and trigger summary cards
- Change Brief material movers table/cards
- Sizing agreement and disagreement lists
- optional Challenge Brief section
- run summary markdown block
- evidence pointer and source-hash audit panel

## Known Gaps

- raw monthly review run directories are not tracked in Git
- the April sample bundle reflects deterministic outputs, not a fresh live-agent pilot run
- `pm_review` is generated in live flow but not yet included in the frontend bundle
- artifact filenames are not yet unified across deterministic and live flows

## Recommendation

For Week 1 frontend work:

- use `monthlyReviewBundle.json` as the primary contract
- treat `challenge_brief` as nullable
- treat narrative fields as primary and numeric detail fields as optional
- avoid binding the UI to raw artifact filenames
- keep a future slot for `pm_review.md/html`, but do not block on it
